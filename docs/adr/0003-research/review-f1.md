# Adversarial review of F1+ (Opus reviewer, 2026-11-13; condensed) and decisions

**Verdict.** F1+ is still first after fixes: 78, against F2 74 and F3 73 with the same race fixes. That is a
**tie under PROCESS**. It is broken towards F1+ by the examples (the only uniform error and cancel story) and by
reversibility (`spawn` can be added later, but never removed). F1+ must not be Accepted until conditions (a)–(g) are met.

| # | Severity | Finding (counterexample) | Decision |
|---|---|---|---|
| 1 | fatal | Non-atomic container borrow counts and pool entry flags are updated by several children at once (`c.go(fn() { if x = names.get(i) … })` ×4) | **Adopt.** A container borrowed *shared* into a crew is **frozen** for the crew's life (a freeze count set before the threads start and cleared after the join). Frozen borrows skip the count, and any write traps. A container borrowed *mutably* goes to exactly one child. |
| 2 | fatal | A non-escaping closure that mutates captures runs on many threads (`par_map(xs, 4, fn(x) { n = n + 1 … })`) | **Adopt.** An inferred per-parameter flag, "reaches a crew child", on the existing call graph. A closure passed to such a parameter may not mutate its captures, and its captured data is frozen. The error suggests `Mutex` or `Atomic`. |
| 3 | fatal | Borrows outlive their owner: a loop-local `buf` borrowed by a child; `c` passed down and used from another function; grandchildren; module state reached through a parameter | **Adopt.** A child may borrow only variables declared in the function that opens the crew, at or above the crew block's level. Anywhere else, `c.go` takes a moving closure. Passing module state to a parameter that reaches a crew child is a compile error. |
| 4 | serious | The "Live crew" is a detached spawn under another name and was never built | **Adopt.** Drop it. The main loop is `crew c { app.run(c) }`. Handlers receive `c` as a call-length borrow, use moving `c.go`, and drain results with `try_recv`. |
| 5 | serious | "No call that may lock while a lock is held" has false positives (print, send, callbacks) and leaks across library boundaries | **Adopt.** A run-time rule in all builds: holding a user `Mutex` while acquiring another, or while making any blocking call, traps with both sites (re-lock is a special case). Stdlib leaf locks are exempt. A nested `lock` that is lexically obvious is a compile error. `lock a, b { }` takes several locks in a fixed order. |
| 6 | serious | Cancellation half-specified | **Adopt.** Cancellation points are blocking calls (`recv`, a blocking `send`, `sleep`, `join`, and stdlib I/O built on poll plus a wake handle) and `c.check()`. Lock acquisition is never one. CPU loops need `c.check()`; nothing is inserted silently. Not cancellable: regular-file reads, DNS and FFI; the list is in the stdlib docs. Blocking calls inside `drop` ignore cancellation. The parent body is inside the cancel scope, and inner tokens are children of outer ones. A cancelled call returns the closed result. `c.go` returns a handle with `cancel()` for per-job cancellation. |
| 7 | serious | Error re-raise | **Adopt.** The first error is re-raised with "plus N more" (all printed in debug builds). The parent's error wins over the children's. Cancellation-caused exits are filtered out. An early exit (return, break, error) cancels, then joins. The error mechanism is D4's. |
| 8 | serious | All-blocked detection never fires in apps | **Adopt.** Debug builds detect cycles in the wait-for graph; endpoints record their holder thread. Release builds keep a per-thread "waiting on X at S" slot (one store per blocking call), printed by a thread dump on SIGQUIT or Ctrl+Break. That inspects threads, not objects, and reclaims nothing, which reads as consistent with R3 and R4. |
| 9 | serious | `each_part` needs a slice type | **Adopt.** A built-in `Part of T`, a borrow-only view that can't be stored. Added to ADR-0002's frozen set (a recorded change). |
| 10–13 | minor | send-then-drain-after-brace deadlock; sending a borrow; silent B2; `c.go` in loops | A debug lint for 10. 11 is already a compile error (`send` takes). 12 is stated. 13 is covered by 3. |

The honest rule count is about 14 (see the ADR).
